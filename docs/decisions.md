# 설계 결정 기록

결정마다 날짜, 결정, 이유를 한 줄로 남긴다. 상태가 **잠정**인 줄은 사용자 확인 없이 추천안으로 정한 것이다.

"임시 모델"은 규칙을 그대로 옮겨 저장소 밖에서 돌려 본 계산 스크립트다. 지도와 수치가 임시값이라 숫자는 방향만 참고한다.

## 규칙

| 날짜 | 결정 | 이유 | 상태 |
| --- | --- | --- | --- |
| 2026-11-13 | 게임은 별도 저장소 `tidetown`에 둔다 | 백준 자동 푸시 저장소와 섞지 않기 위해 | 확정 |
| 2026-11-13 | 배치 점수는 놓는 순간 한 번만 계산하고 이후 바꾸지 않는다 | v0 문구("즉시 계산")와 맞고 테스트가 단순하다 | 확정 |
| 2026-11-13 | 부두의 물때 점수는 +3에서 인접 부두 1개당 −1 | v0의 부두는 수입도 주고 시장·등대·덕장의 점수 재료도 되면서 대가가 없었다. 등대와 시장은 부두를 모으게 하고 수입은 떼어 놓게 해서 배치에 고민을 만든다 | 확정 |
| 2026-11-13 | 집에 "인접한 물 칸 1개당 +1"을 넣는다 | v0는 6종 중 4종이 물때와 무관해서 물때가 선택을 만들지 못했다. 같은 칸의 가치가 물때마다 달라지게 한다 | 확정 |
| 2026-11-13 | 고르지 않은 손패는 덱 아래로 돌린다 | v0 유지. 타일 가치가 물때에 따라 달라지면 놓는 순서에 의미가 생긴다 | 확정 |
| 2026-11-13 | 배치 대신 손패 1장을 버릴 수 있다. 놓을 수 있는 타일이 없으면 버려야 한다 | v0는 놓을 수 없는 타일(두 번째 등대 등)이 덱에 영영 남아 판이 끝나지 않았다 | 확정 |
| 2026-11-13 | 버리기는 턴이 아니고 물때를 움직이지 않는다 | 버려도 물때가 흐르면 건물을 그만 짓고 버리기만 하며 수입을 받는 전략이 통한다. 임시 모델에서 건물 17개만 놓고 버리기만 한 쪽(112점)이 매 턴 최고점을 고른 쪽(104점)을 이겼고, 수입 우선 전략은 보드를 채운 뒤 평균 56번을 버리며 13단계까지 갔다. 물때를 배치에만 묶으면 각각 53점 대 71점, 버림 0회와 5단계가 된다 | 잠정 |
| 2026-11-13 | 남은 타일 중 지금 놓을 수 있는 것이 없으면 판을 끝낸다 | 물때가 배치로만 바뀌므로 남은 타일을 하나씩 버리는 것과 결과가 같다. 의미 없는 버리기를 반복시키지 않는다 | 잠정 |
| 2026-11-13 | 집에도 "인접한 덕장 1개당 −1"을 넣는다 | 덕장에만 감점이 있으면 덕장을 먼저 놓고 집을 붙여 감점을 피할 수 있다 | 잠정 |
| 2026-11-13 | 목표 점수, 시작 덱, 묶음 구성은 임시값으로 시작한다 | 시뮬레이터로 조정할 예정이다. 임시 모델에서 무작위 봇은 주로 1단계, 매 턴 최고점 봇은 4단계, 수입 우선 봇은 5단계였다 | 잠정 |
| 2026-11-13 | 클리어 조건은 두지 않는다 | v0에 끝나는 조건이 "타일이 없는데 목표 미달" 하나뿐이었다 | 잠정 |
| 2026-11-13 | 거리는 가로 차이와 세로 차이의 합으로 센다. 등대 반경 2는 최대 12칸이다 | 인접(4방향)과 반경을 한 기준으로 다룬다 | 잠정 |
| 2026-11-13 | 썰물로 시작하고 4번째 턴의 배치 직후에 물때가 바뀐다 | 첫 턴부터 염전을 놓을 수 있고, 첫 전환이 밀물이라 부두 수입을 일찍 보여 준다 | 잠정 |
| 2026-11-13 | 전환 점수는 그 순간 보드의 해당 건물이 모두 받고, 방금 놓은 건물도 받는다 | 예외가 없는 쪽이 설명과 구현이 쉽다 | 잠정 |
| 2026-11-13 | 배치 조건은 놓는 순간에만 검사한다 | 물때가 바뀔 때마다 건물이 무효가 되면 밀물에 놓은 부두를 설명하기 어렵다 | 잠정 |
| 2026-11-13 | 지형 판정은 건물과 무관하고, 보드 밖은 칸이 아니다 | 판정을 지형 하나로만 하면 규칙이 한 곳에 모인다 | 잠정 |
| 2026-11-13 | 갯벌에 놓을 수 있는 건물은 염전뿐이다 | v0의 타일 표를 따른다 | 잠정 |
| 2026-11-13 | 집의 시장 점수 +2는 시장이 여러 개여도 한 번이다 | v0 문구("인접 시장이 있으면")를 따른다 | 잠정 |
| 2026-11-13 | 목표는 "이상"이면 달성이고, 턴 끝에 물때 점수까지 더한 뒤 판정하며, 한 턴에 여러 단계를 달성할 수 있다 | 점수가 목표와 같을 때 달성으로 보는 쪽이 자연스럽고, 판정 시점이 하나면 순서 문제가 없다 | 잠정 |
| 2026-11-13 | 묶음은 단계별 고정 구성을 묶음 안에서만 섞어 덱 아래에 넣는다 | 구성이 고정이면 밸런스를 맞추기 쉽고, 기존 덱 순서를 건드리지 않으면 재현이 단순하다 | 잠정 |
| 2026-11-13 | 수치의 현재 값은 `data/*.json`이, 규칙의 형태는 `docs/rules.md`가 기준이다 | "수치는 json에서 조정한다"와 "문서가 기준이다"를 함께 지키기 위해 | 잠정 |

## 구조

| 날짜 | 결정 | 이유 | 상태 |
| --- | --- | --- | --- |
| 2026-11-13 | `Tide`는 물때 시계만 맡고, 물때 점수는 `Scoring`이 계산하고 `GameState`가 호출한다 | 점수 계산을 한 클래스에 모으고 `Tide`를 가볍게 둔다 | 확정 |
| 2026-11-13 | "밀물의 갯벌은 바다" 판정은 `Tide.effective_cell` 한 곳에만 둔다 | 배치와 점수가 서로 다른 판정을 쓰는 일을 막는다 | 확정 |
| 2026-11-13 | 배치 조건과 점수 규칙을 json의 `flat`, `count` 두 종류로 표현한다 | 6종 전부가 이 둘로 표현되고, 새 타일을 코드 수정 없이 추가할 수 있다 | 확정 |
| 2026-11-13 | 물때 주기, 손패 장수, 덱, 목표는 섬 json에 둔다 | 새 데이터 파일을 만들지 않는다. 섬이 늘어 공통 수치가 생기면 나눈다 | 확정 |
| 2026-11-13 | 섬 데이터 검증은 `GameState.validate_island`에 둔다 | 새 파일을 만들지 않는다. 커지면 따로 나눈다 | 확정 |
| 2026-11-13 | 난수 생성기는 `GameState`가 하나만 만들어 `Deck`에 넘기고, `Deck`이 직접 섞는다 | `Array.shuffle()`은 전역 난수를 써서 seed로 재현되지 않는다 | 확정 |
| 2026-11-13 | 시뮬레이터 봇의 무작위는 게임과 다른 난수 생성기를 쓴다 | 봇이 바뀌어도 같은 seed의 덱 순서가 유지된다 | 확정 |
| 2026-11-13 | 묶음은 타일 id를 사전순으로 펼친 뒤 섞는다 | 결과가 json의 키 순서에 달라지지 않게 한다 | 확정 |
| 2026-11-13 | 점수 테스트를 규칙 엔진 테스트와 v1 데이터 테스트로 나눈다 | 수치를 조정해도 엔진 테스트는 깨지지 않고, 문서의 예시와 실제 데이터가 맞는지는 따로 확인한다 | 확정 |
